# API — the channel an agent pulls from

An AI agent can pull a finished episode from here and post it elsewhere with no
human copying. Everything is generated by `scripts/build_api.py` from the same
`scenes.json`, `timing.json` and `meta.json` the video was built from, so the
channel cannot drift away from what was actually published.

Start with `GET /llms.txt` — a plain-text orientation written for agents.

## Read

| Endpoint | Returns |
|---|---|
| `GET /llms.txt` | orientation for an AI agent |
| `GET /api/index.json` | catalogue: every episode, with URLs and tags |
| `GET /api/episodes/<slug>.json` | one episode in full |
| `GET /api/receipts` | what has been posted so far (addresses masked) |
| `GET /feed.xml` | Atom feed with `rel="enclosure"` media links |
| `GET /sitemap.xml` | crawler map |

### The episode object

| Field | Meaning |
|---|---|
| `id`, `slug` | `ep01`, `ep01_gift_of_the_magi` |
| `title`, `title_en`, `series` | display names |
| `duration_sec`, `duration_hms` | length |
| `source` | work, author, year, licence, source URL |
| `media.video.url` | **permanent** download link (GitHub Release) |
| `media.audio.url` | **permanent** download link |
| `media.poster.url` | poster art (committed to git, so raw GitHub) |
| `media.audio.lufs`, `true_peak_dbfs` | loudness, for reference |
| `chapters[]` | `start`, `time`, `title` — a ready YouTube chapter list |
| `script` | the full Thai narration as text |
| `posting` | text already shaped for each platform |
| `credits[]` | image licences and creators, for attribution |

### `posting`

Ready to post, no rewriting needed:

* `posting.youtube` — `title`, `description` (with chapters, source and
  attribution already in it), `tags`, `category_id`, `language`, `made_for_kids`
* `posting.facebook` — `caption`
* `posting.tiktok` — `caption`
* `posting.blog` — `title`, `excerpt`, `body_markdown`
* `posting.hashtags` — the tag list

## Write

One endpoint, so an agent can report what it published:

```bash
curl -X POST https://<base>/api/receipts \
  -H "Content-Type: application/json" \
  -d '{"episode":"ep01","platform":"youtube","url":"https://youtu.be/XXXX"}'
```

Returns `201` with the stored record. Rules:

* JSON object only, 1 byte to 64 KB.
* Any other POST path returns `404`.
* The body is stored **verbatim** and appended to `receipts/receipts.jsonl` —
  which is outside `site/`, so it is never served, and it is gitignored. The
  caller's address is recorded but shown masked on `GET`.

## MCP — the channel as tools

An AI that speaks MCP needs no URLs at all. `scripts/mcp_server.py` exposes five
tools: `list_episodes`, `get_episode`, `get_posting`, `report_posted`,
`list_posted`. It talks to this same HTTP API, so there is one source of truth.

```json
{
  "mcpServers": {
    "thai-story-channel": {
      "command": "python3",
      "args": ["/abs/path/to/content-lab/scripts/mcp_server.py"],
      "env": { "CHANNEL_BASE": "https://<host>" }
    }
  }
}
```

A ready copy is at `mcp.json`. Verified over the stdio protocol: `initialize`,
`tools/list`, and calls to `list_episodes`, `get_posting`, `report_posted`,
`list_posted` and `get_episode`.

## The client

```bash
python3 scripts/post.py --list
python3 scripts/post.py ep01 --platform youtube
python3 scripts/post.py ep01 --platform blog --json
python3 scripts/post.py ep01 --download ./out
python3 scripts/post.py ep01 --platform youtube --report https://youtu.be/XXXX
```

`--base` overrides the channel URL; `CHANNEL_BASE` sets it for a session.

## Instructions for the agent

`GET /llms.txt` carries the publishing instructions inline, so an agent that
reads it needs nothing else. For a copy-paste prompt or the MCP registration,
see `docs/AGENT-PROMPT.md`.

## Regenerating

```bash
python3 scripts/build_api.py                 # after adding or editing an episode
python3 scripts/build_api.py --base-url https://your.host
```

An episode is picked up when `episodes/<slug>/scenes.json` exists. Optional
`episodes/<slug>/meta.json` supplies the title, description, tags and release
tag; sensible values are derived from `scenes.json` when it is absent.

## Honest limits

* The sandbox link dies when the pod is recycled, so the **live** API is
  temporary. The permanent artefacts are the release URLs and the raw GitHub
  URLs, both of which appear in every episode object.
* Writes go to a file on the sandbox disk, so receipts do not survive a recycle.
  Treat them as a local log, not as a system of record.
* There is no authentication. The write endpoint is a log, not a database — do
  not put anything confidential in it.
